Wren is a development environment for Digicool's 8-bit OLED Thing and 8-bit LED Thing. You write Wren BASIC in it, run and debug the program on an emulated Thing, and upload, run and debug it on a real one through a programmer.

**This is a beta.** The Raspberry Pi Pico programmer has been used on real OLED Things and LED Things. The ST-LINK V2 has not been tried with this build yet.

**New since beta 2:**
- **Digicool's firmware comes from Digicool.** Wren no longer carries it. **Tools → Firmware…** fetches it from Digicool's GitHub when it opens, along with any newer version, and **Write image…** opens the folder it keeps it in. A Thing still running OLED Thing firmware v1.0 is now recognised too.
- **A compact emulator.** The emulated board takes less room and the program gets it. **View → Large Emulator** brings back the large one.
- **Folders remembered.** **Open** and **Save As** start in your program's folder, and **Write image…** in the folder you last wrote an image from, each kept apart from the other.
- **New programs** in `programs\OledThing`: a stopwatch, a voltmeter, a latch and a latch-speed test, a frequency counter, a logic analyzer, a bus sniffer, a serial decoder, and `Touchstone.bas` for the Touchstone-86 chip tester's displays. The Arduino Mega sketches that feed the instrument programs are in `firmware`.
- A little room between the editor's line numbers and the program.

## Getting started

1. Download `Wren-0.1.0-beta.3-win-x64.zip` below and unzip it anywhere: it needs nothing installed (64-bit Windows 10 or 11).
2. Run `Wren.exe`. It opens `programs\OledThing\OledThing.bas`, the OLED Thing's own behaviour written in Wren BASIC.
3. Press **F5** to run it on the emulated Thing, with the debugger: **F9** sets a breakpoint, **F10** and **F11** step.
4. **Board** chooses the OLED Thing or the LED Thing; **Help → Wren BASIC quick reference** has the language on one page; **View** has Dark Mode and Large Emulator.

## On a real Thing

- **The programmer:** a Raspberry Pi Pico (or Waveshare RP2040 Plus) with `firmware\PicoLink\PicoLink.uf2` on it, or an ST-LINK V2. **Tools → Firmware…** has the wiring for each.
- **Once per Thing:** **Tools → Firmware…**, **Connect**, **Install kernel**. Wren finds which Thing it is and installs that board's kernel. To put a Thing back as it came, **Write image…** with Digicool's firmware for it.
- **Then:** **Debug → Target → Thing on the programmer**. F5, Ctrl+F5 and the stepping keys work on the Thing. A program is uploaded only when it changed, and blocks the Thing already holds are reused, to spare its flash (rated for about 100 writes a block).

## What is in it

- Wren BASIC: event handlers (`ON CHANGE`, `ON LATCH`, `ON EVERY` ...), 16-bit integers, arrays, SUBs and FUNCTIONs, with syntax highlighting.
- The OLED Thing: drawing, text in four fonts, the mode pins, analog inputs. The LED Thing: `LEDS` and its mode pins `M0`-`M2`.
- Programs in `programs`: both Things' own behaviour, demos (scanners, Snake, Pong, hex readouts at any angle), and the instruments above.
- The kernel in STM8 assembly, the emulator, and a debugger that runs on the Thing's own chip.

## Known limits

- **ST-LINK V2:** untested in this build. Wren opens it through WinUSB, as ST's own driver does. If **Tools → Firmware…** does not find yours, please open an issue saying what Device Manager shows for it.
- **Debugging on a real Thing:** two breakpoints at a time (the chip's), and stepping is slow through a Pico, about 50 ms a bytecode instruction.
- **Digicool's firmware** needs the internet once, the first time **Tools → Firmware…** opens; after that it is kept on your machine.
- Windows only for now.
